# AutoIM PC 端企业微信界面识别规范 V1.3

版本 V1.3 · Windows PC · 企业微信 Windows 版 · 初始验收要求窗口最大化。

规范源自用户提供的真实截图及界面行为说明。参考图大小为 1920 × 1023，当前附件与仓库没有该图文件。真机样本只在经授权的测试会话中采集，含真实身份或聊天内容的图像和识别结果不进入公开仓库。

## 用户确认的界面规则

| 区域 | 含义与观察规则 |
|---|---|
| A | 左侧功能区，包括头像、消息、频道、邮件、文档等入口。识别消息页及区域边界。消息入口右侧的红底白字数字反映非静音会话的未读情况。 |
| B → B1 | 最近联系人区顶部固定工具栏，左为搜索，右为灰底加号。文字及图标不属于联系人列表。 |
| B → B2 | 独立滚动的最近联系人列表。头像右上可能有红点或白字红徽标，数字不明时未读数为空。中间两行分别为名称、预览，右侧为静音与原始活动时间。静音联系人仍计入未读。选中高亮和未读相互独立。 |
| C → C1 | 会话标题与可见身份信息。将手机号、明确识别的身份标签和可分离的组织信息从显示姓名分开。无身份标签冲突时，两个可靠姓名一致为 `VISUAL_MATCH`，一致性不足为 `UNKNOWN`，两个可靠姓名确实不同时为 `CONVERSATION_MISMATCH`。唯一身份保持未验证。 |
| C → C2 | 独立滚动的历史区。左侧消息容器是对方消息，右侧消息容器是自己的消息。方向取决于容器对齐，颜色仅协助找边界。居中时间、系统提示、引用和卡片需要单独处理。 |
| C → C3 | 输入区、工具栏、草稿及右下发送按钮。按钮通常在空输入时浅、非空时深。外观不能证明已发送，草稿不能进入历史消息。 |

B2 最近联系人、C2 历史和 D 群看板是三个独立滚动区。内容超过一页并且鼠标位于各自区域时，滚动条可能出现；内容不足一页时悬停也可能没有滚动条。没有滚动条不能作为区域不存在的证据。C1、C3 的悬停不触发 C2 滚动条。

A 区全局未读输出徽标可见性、数字和可靠性。入口不可确认时可见性为未知。全局数字与 B2 联系人头像徽标分别检测、分别显示。静音会话继续纳入 B2 未读检测，暂不推断两组数字的聚合关系。

## 识别算法与假设

- 验证目标窗口身份、矩形、窗口状态及采集前后 DPI。仅请求目标 HWND 渲染，图像保留于内存。最大化前提无法满足、窗口变动、渲染失败或全黑时报告失败。PrintWindow 绘制范围可能超过 Win32 客户区尺寸。用带标记的缓冲区测量绘制范围，要求右侧、底部均有未绘制边带，同时检查比例和黑边。无法确认覆盖时报 `CAPTURE_INCOMPLETE`。
- A/B/C 的垂直分界和 B1/B2、C1/C2/C3 的水平分界使用相对搜索范围、持续边缘及区域几何。背景色变化可辅助识别。用户可用同一截图链路标定 A 和五个子区域。输出八个区各自的像素坐标、归一化坐标、自动或人工来源和失败证据。局部区失败时保留其余有效区域，允许用有效的单区标定补足。C2 延伸至底缘或与 C1/C3 重叠时不解析该裁剪。
- B2 从头像、高亮、OCR 名称列和相邻行节距生成联系人候选，在各行分区读取名称、预览和活动时间。机器人、群聊和系统会话使用同一生成规则，类型只作为观察候选。底部缺少标准头像或预览仍可保留行，视口截断的行标为 `PARTIALLY_VISIBLE`。徽标需要位置、红色连通区域和几何证据。数字需要独立 OCR 证据。静音斜线与高亮色块是待实测视觉判据。滚动条是可选证据。
- C2 使用通用前景轮廓、背景补偿和独立蓝色填充证据寻找消息容器，再关联同一原图坐标系中的 OCR。关联要求中心点、横纵重叠、受限外溢边距和唯一候选。接近头像尺寸的蓝色方块需要正文证据才能参与锚点。容器左右边缘与标定或候选内容锚点按截图比例比较。两侧冲突、无可靠对齐或消息被截断时保留 `UNKNOWN`。文件名与尺寸可支持文件候选，媒体正文保持未读取。
- OCR 在本机对已划分的区域运行并返回文字、置信度与像素框。活动时间保留“X分钟前”、HH:mm、MM/DD、“昨天”或星期等原文。居中时间仅作为可见上下文，不补全日期或年份。聊天消息按容器 Y 坐标排序，同文消息保留为两条。
- 自动分界、头像形态、徽标、静音图标、高亮、容器轮廓、锚点、媒体外观和正文 OCR 的阈值均属算法假设。合成图像测试不能替代真机核对。

识别与 OCR 使用原始渲染像素。预览使用 Qt 逻辑像素，窗口大小受显示器工作区约束。默认整图保持宽高比，缩放和切回标签时重绘。图像与叠加框共用由实际视口推导的比例和偏移。记录 Win32 客户区、原图、QImage/QPixmap 尺寸与 DPR、预览逻辑尺寸、比例和偏移。V1.2 标定保存到独立文件，标定坐标以完整原图为基准。

## 观察记录及错误状态

| 记录 | 字段 |
|---|---|
| 窗口与布局 | PID、HWND、窗口矩形、最大化、截图宽高、DPI、采集时间、页面类型、鼠标所处区域、各区域边界及证据。 |
| 联系人行 | 行号、头像和行框、显示名、预览、未读证据和数字、静音、活动原文、选中状态。证据不足时为空或未知。 |
| 会话 | 标题、可见身份文字、选中行、匹配状态、可见消息数。会话类型不明时为 `UNKNOWN`，唯一会话身份保持未确认。 |
| 可见消息 | 顺序、容器框、方向、类型、OCR 内容与原文证据、左右对齐距离、可见时间标签、采集时间和识别状态。 |

诊断分层呈现采集耗时、识别耗时、八区状态、联系人和未读计数、全部消息框候选及方向统计、OCR 初始化与各裁剪的文字和分数、消息解析及会话归属。保留未归属 OCR 文字、未通过分类的消息框、失败裁剪和未识别原因。OCR 初始化成功只说明引擎可用。OCR 找到文字后仍需匹配独立的消息框。

C2 每个 OCR 文字块仅有一个去向，包括 `MESSAGE` 正文、`TIME` 时间标签、`SYSTEM` 系统提示、`MEDIA` 媒体或文件卡片，以及 `UNASSIGNED` 待排查。未归属记录保留原文、置信度、原图坐标、最近候选框和失败原因。未归属的正文候选或明显截断使状态为 `VISIBLE_MESSAGES_INCOMPLETE`。缺少充分检测证据时为 `VISIBLE_MESSAGES_UNVERIFIED`。已观察到的文字和容器完成归属时为 `VISIBLE_MESSAGES_ACCOUNTED_FOR`，范围仅限检测到的候选，不证明不可见历史或当前画面所有消息均已检测。B2 未使用的 OCR 文字在联系人诊断中保留过滤原因。

截图以 `WINDOW_UNAVAILABLE`、`WINDOW_CHANGED`、`NOT_MAXIMIZED`、`WINDOW_MINIMIZED` 或 `CAPTURE_FAILED` 报告异常。布局失败、OCR 不可用、边界含糊及剪裁都需要显示原因。会话不匹配时保留独立的屏幕观察并禁止会话归属。完整性始终限于当前视口，滚动后出现的历史内容不能认定为新消息。记录没有企业微信官方消息 ID 或联系人 ID。

## 安全与验收

单次按钮触发窗口截图、布局和局部 OCR。窗口、截图、消息及草稿在内存中处理。无剪贴板取数、鼠标移动或点击、键盘操作、切换会话、滚动、写入、发送、私有数据读取或联网推理。保留 Windows Driver 真实点击安全闩。

完整的视觉验收清单包括 Windows 11 最大化企业微信中的八个区域、联系人未读与选中分离、标题匹配、左右文本、图片和文件、草稿隔离、未最大化与窗口变化，以及在不同 DPI 下观察 B2、C2、C1 或 C3 的悬停与滚动条。PC-V1 的已验收范围见下文 V1.3 记录。

采集使用 [Microsoft PrintWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-printwindow) 请求目标 HWND 渲染其客户区。该调用为同步操作，在后台执行。部分客户端可能无法用这一接口返回可用画面，应记录 `CAPTURE_FAILED` 并在授权设备上核对。文字识别使用本机 CPU 与随包模型。[RapidOCR 模型说明](https://rapidai.github.io/RapidOCRDocs/main/en/model_list/)

## 第一次真机失败与修复证据

用户报告 Windows 企业微信在 DPI 168（175%）下，旧版预览仅见左上部分，布局为 `LAYOUT_UNCERTAIN`。本机复测的物理客户区为 1925 × 1025。扩大 PrintWindow 缓冲区测得完整绘制范围 2696 × 1436，旧图与该范围的左上 1925 × 1025 逐像素一致。新增的右下区域检出了发送标签。旧诊断窗口初始逻辑尺寸 1120 × 740，同一显示器 1920 × 1020 的物理工作区约为 1097 × 583 逻辑像素，初始窗口超出可用空间。

修复后的受控 Qt 175% 测量中，1063 × 431 逻辑视口显示了完整图像，内容大小 809.2 × 431，缩放 30.01%，水平偏移 126.9。抽样比对右、底像素一致。只读实机帧可得到八区、全局未读 3、联系人和标题证据。该次尚未核对消息框归属及方向。[Qt 高 DPI 坐标说明](https://doc.qt.io/qt-6/highdpi.html)

## V1.3 实机验收反馈与修复

用户提供的后续验收记录为 2696 × 1436 原图、DPI 168、八区基本正确且全局未读为 3。联系人列表底部漏掉机器人和系统会话行，同一会话因 C1 首行混有手机号和组织信息而被判为错配，两条可见右侧文字已被 OCR 高置信识别却未分配到容器。

排查确认旧 B2 依赖标准头像或高亮才能生成行。旧 C1 只识别少数显式分隔符，随后比较整行。旧 C2 依赖全局前景及有限条件下的背景补偿，且 OCR 归属要求横向边距很紧。它先把文字中心在任一候选框中的文字从未归属清单排除，再尝试正式关联和分类，两次判据不一致导致文字消失。两条真实气泡具体在哪条轮廓或边距检查失败，仍待原图复验。

V1.3 修复限于联系人行、标题比较、消息容器、OCR 归属和 GUI 诊断。修复时工作区未找到获授权的原图。回归 154 项通过、0 项失败，其中 22 项为 V1.3 新增。脱敏合成图中的六条消息按顺序提取，包含浅蓝长短气泡与近边缘文字。

用户在 Windows 11 企业微信复验确认以下五项，PC-V1 可见消息读取标记为 `DONE / VERIFIED`，范围限于用户已验证的可见聊天场景。

1. 可以获取完整窗口截图。
2. 可以定位 A、B、C 及各子区域。
3. 可以读取联系人列表，底部遗漏已修复。
4. 可以读取当前标题并修复选中行误匹配。
5. 可以读取六条可见消息，包含此前遗漏的两条右侧蓝色消息，并区分普通消息的左右方向。

## PC-V2 当前会话持续监测

用户已报告 PC-V2.2 的文件识别和诊断复制在 Windows 11 企业微信通过。V2 复用 V1.3 的窗口、截图、分区、容器和本地 OCR。开始、停止与展示均在现有视觉诊断面板，截图和识别在单个后台任务内运行。

- 默认采样 2 秒，可设为 1–30 秒。首次识别用于发现布局及验证会话。后续比较缩小的 C2、C1 与 B2 选中行侧栏。C2 排除滚动条边带，C3 草稿不进入比较。像素容差、局部聚集以及连续两帧稳定门槛共同抑制闪烁和动画。完整识别结束后有 2 秒冷却。串行任务结束才调度下一轮，失败退避上限 30 秒。
- 首次可靠观察进入 `BASELINE_CREATED`，现有可见消息进入基线。后续用消息类型、方向、规范化正文或图片缩略像素，在同一连续会话内比较有序序列及容器移动。新增要求可靠旧序列重叠、尾部独立追加及每条追加所在区域的像素变化。仅用于认定序列无变化的轻微 OCR 抖动保持原基线。同文按位置和出现次数保留。候选记录含时间、方向、类型、正文、原截图容器、OCR、视觉顺序、匹配状态和完整性风险。
- 可靠追加进入 `VISUAL_NEW_CANDIDATE`，稳定或未见有效变化时显示 `NO_CHANGE`。等待画面稳定显示 `MONITORING`。可见滚动条离开底部、顶部插入、底部消失或重叠歧义会阻断候选。旧消息上移较大或离开视口时需要前后均有底部滚动条证据。鼠标在历史区且画面随序列整体移动时重同步。
- PID、HWND、窗口位置、尺寸、DPI、布局、选中行与标题变化均会核对连续性。可见同名行、无头像时选中行位置变化、头像或标题附加证据变化会阻断会话拼接。视觉身份始终未获得唯一性验证。同名、同头像和相同标题且无可见区别时，视觉方法无法证明同一身份。
- 会话或窗口变化、手工滚动迹象进入 `RESYNC_REQUIRED`。布局、会话或全部消息证据不可用时进入 `OBSERVATION_UNRELIABLE`，已定位的个别缺失按下文部分基线处理。窗口不可用或截图失败时进入 `PAUSED`。恢复时以稳定画面建立基线。停止进入 `STOPPED`，正在执行的原生调用返回后丢弃结果。
- 截图只在本地内存中短暂使用，监测面板保留最近 100 条候选与 80 条状态诊断，可清空。普通日志不写候选正文。监测仅限打开的会话，未接入自动发现、切换、滚动或发送。视口之外、程序停机期间和两次采样之间的完整性未知。没有官方 `messageId` 或可靠唯一客户身份。消息方向和媒体类型沿用 V1，支持普通文本、识别到的图片和文件卡片候选。

### 首轮真机姓名错配与基线门禁修复

首轮真机中，B2 将 `姓名@微信` 作为显示名，C1 返回无后缀的姓名。精确比较误判两者不同，监测停在 `OBSERVATION_UNRELIABLE` 且基线为 0。头像和标题附加证据原先也有独立的阻断门禁，缺少这类证据的普通姓名会话现可建立基线。

- B2 和 C1 诊断分别保留原始名称、显示姓名和身份标签。支持 ASCII 与全角 @。明确的 `微信`、`微信联系人` 及其组合识别为 `PERSONAL_WECHAT`。带可靠组织名称特征的单个企业标签识别为 `EXTERNAL_WECOM`。公司名含“微信”仍按组织判断。仅有姓名时可做视觉核对，联系人分类保持未知。
- 身份标签结构不明、冲突、截断或 OCR 不可靠时返回 `UNKNOWN`。只有可靠姓名用于精确比较。可用窗口、消息页、可靠选中行、`VISUAL_MATCH` 和可靠可见消息满足时，首个可靠观察建立基线并生成 0 条新增。唯一身份未验证不构成门禁，头像、标题辅助字段及选中行位置可用于变化检查。
- 面板单独报告页面及选中行状态、两侧名称原文和解析结果、标签、视觉匹配、可靠可见消息与连续稳定采样次数。基线阻断时显示直接原因。同名联系人的唯一身份仍未知，观察到同名歧义或切换证据时阻断旧会话连续性。

### PC-V2.1 部分基线与新增判定

用户后续实测已达到 `VISUAL_MATCH`，C2 显示 `VISIBLE_MESSAGES_INCOMPLETE`，监测仍报 `OBSERVATION_UNRELIABLE` 且基线为 0。旧服务要求聚合完整性和所有消息状态同时通过，任何一次失败都使有效基线失效。合成回归复现了一条旧消息低置信、其他消息可读的情况。真实失效的具体容器或 OCR 未提供逐条证据。布局范围或无头像时选中行位置变化也可能保守重同步，现有真机报告没有指向这条路径。

- 原始观察在内存保留已解析消息、OCR 字块和未确认容器。已匹配的时间和系统提示单列为上下文，不计入消息候选。可能是正文的未归属 OCR 保留坐标、文字、置信度和原因，缺乏容器时方向未知。文件名可见但大小不足的疑似卡片、图片占位、引用或转发等复杂卡片列为不可靠。区域 OCR 失败独立记录，缺失位置未知。
- `PARTIAL_BASELINE` 表示保留了部分可读旧消息。面板列出可定位的候选、可靠和不可靠数，区域级缺失另记。可靠基线为 `BASELINE_CREATED`，表示已识别的可见序列足以比较。两种基线的首次观察都产生零条候选。部分基线静止时按不低于 10 秒且不短于五个采样周期的间隔补读，原地补读只更新基线。

- B2 按每轮可信的可见行顺序处理，每次处理后从新截图取得最新行坐标。局部阻断延后四轮复核，全局阻断等待恢复。相同未读更新原有任务观察，数量增加或可靠预览变化可创建新任务。连续 12 次未完成的导航尝试触发保护，成功完成重置计数。

真机复验用授权测试账号。手动最大化企业微信，再在 AutoIM 授权，切回企业微信并等待核验。核对资料退出、邮箱和本地绑定。在测试会话准备未读后验证从上到下的导航、截图、SQLite 与历史查询，随后测试 AutoIM 最小化时 F10 能停止。当前记录包括 Windows 上的只读窗口和输入证据，以及在独立 Qt 窗口中真实注册和注销快捷键。邮箱和消息采集闭环待真机验收。

### PC-V3.5.2 真实导航修复与限时验证

- 气泡为独立、输入透明及不激活的 Qt 工具窗口，默认屏幕右下，双屏时优先避开企业微信所在显示器。正常截图仍用企业微信自身的 PrintWindow 客户区。175% DPI 真机已核对最小化显示、前台未被抢占、命中穿透，及气泡显示前后 C2 像素一致。

### PC-V3.5.3 多特征视觉定位与时间锚点

- 核心测试在原图坐标内单独读取 B2 右侧时间，接受归一化后的钟点、昨天、星期、月日、刚刚及分钟前。以相邻时间锚点、灰色线、蓝色带或头像间距估计当前行高。灰线由横向亮度一致性及上下局部对比确认，蓝色带由连续背景像素确认，触及视口的行继续单独标记。B2 时间只代表联系人活动。
- B2 红色连通域先独立检测，以大小、填充、徽标列、头像右缘和行内锚点核对。可从红标和行边界补生成候选。A 区总未读使用自身区域，未归属 B2 徽标单独计数。静音由局部归一化后的铃铛匹配及数字徽标共同判断，小红标本身不能确认静音。证据冲突待核。仅原始名称「折叠的聊天」匹配折叠入口。

- C2 正文按气泡排序。可靠的可见独立时间才填写消息实际时间。共享标签保留原文、时间段来源、分钟或相对精度及段内顺序。星期或缺年份日期须有近期页面或前序日期的证据。缺日期的钟点及相对时间可保留原文，无法可靠解出日期时不参与绝对时间比较。
- 阶段 7 按本机默认账号及会话查隔离库。首次保存可靠可见的收发消息，后续先比对时间及有序历史末尾，保留同分钟同文的不同出现位置。缺少可靠重叠时，只有连续且没有未修复缺口的时间锚点允许前移。其他观察进入本地待复核，独立 OCR 不进入事务。事务提交后才更新保存量，停止或超时前未提交的事务回滚。

### PC-V3.5.3.1 完整名称及视觉证据

- B2、C1 和持久化共享完整显示名称。原始 OCR、NFKC 后的完整名、基础名和身份标签分别记录。B2 通过同行、文字高度、横向间距及坐标边界重建分段名称，预览中的 `@` 和右侧时间独立归属。C1 能拆分可核实的附加字段。可靠但不同的完整名称返回会话不匹配，截断和不完整标签保留原样并标记待核。
- 区分完整名称重复、同基础名异后缀及重复行分割。完全同名时只有结构可靠且徽标及目标点独立的行可进入受控点击。点击后核对选中行位置、完整标题、徽标消失和 C2 刷新，明确冲突时拒绝归属。完全同名的界面观察可展示待复核，隔离历史只复用按完整名确认的记录，旧版基础名记录保持原样。
- 核心测试异步保存全行扫描明细与代表性 B2、导航前后、C1、C2 及失败区裁剪。私有记录关联检测、扫描、任务、事件及截图 ID。证据不参与放行决策。队列满、截图缺失、超限或保留期清理均可在清单显示 `DIAGNOSTIC_EVIDENCE_MISSING`。
- 普通 ZIP 的图像由实际截图坐标生成，底图像素全遮盖。完整 ZIP 由用户显式选择，含原始裁剪和实际 OCR。两个模式均有离线 HTML、结构化联系人与消息文件及文件摘要清单。导出核对事件、坐标、图像尺寸和摘要，中途失败清理未完成文件。

### PC-V3.5.3.2 C2 连续填充、时间与增量

- 常规容器和原图 OCR 优先。对失去关联的可信正文，使用当前 C2 背景色差产生局部候选，在 DPI 适配的开运算去除细笔画后闭合小缺口。再以容器边界、方向、原图 OCR 位置和正文上下连续填充复核。局部色差较低时从正文周围找同色闭合区域，要求存在可独立验证的气泡。空间重叠的结果只归属一次，实际出现两次的同文仍按两个气泡保留。浅、稀疏、有斜向或重复视觉证据且缺少填充的 OCR 可标记为水印。单独表情可归类为表情。
- C2 的裸钟点属于原截图当地当天，「昨天」按当地日历减一天，星期优先取 2 至 6 天前最近匹配日，另记未经证实的边界。无年份月日取一年范围内最近合理日期并标注推断，只有日期时保留日期精度。只对可靠居中且未被消息容器归属的时间文本做限定格式纠错。保留原文、标准化值、纠错、精度与分组顺序。未来时间、逆序、顶部缺时间及相对时间均保留相应不确定性。
- 稳定会话读到可靠正文即可进阶段 7。未读数字和区间独立展示，部分 OCR 失败或低置信正文最多再复核一次，无法用同页证据解决的缺口直接交给历史比对并留档。无法确认会话时仅独立展示。
- 隔离库时间辅助表增量兼容旧记录。旧 C2 时间从旧记录的采集日期重新解释后仅用于比对，旧行保留原值。事务记录覆盖缺口位置及前后时间，未解决缺口禁止仅以时间推进检查点。唯一有序重合仍可确定新增，已证实最新且时间锚点明确的同文尾部可比较出现次数。
- 完整视觉包包含原始前景和形态处理后的掩膜、原图坐标中的 OCR、气泡来源和水印判据，以及原始与标准化时间。普通包遮盖消息和掩膜像素，保留纠错类型、坐标、状态及结果统计。
